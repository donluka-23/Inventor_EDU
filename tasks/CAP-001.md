## 1. Engineering objective

Implement the first read-only capability-discovery adapter that converts a typed GPIO functional requirement into an evidence-qualified domain of real physical board terminals.

The discovery system must:

1. Read the existing exact board catalog and reviewed GPIO fact set.
2. Discover available physical GPIO contacts dynamically.
3. Evaluate requested GPIO functions through the existing verifier.
4. Preserve source evidence, failures, uncertainty and verification coverage.
5. Supply terminal domains to the existing SYN-001 candidate generator.
6. Demonstrate actual generation without manually supplying specific GPIO contact lists.

This is not a general-purpose component catalog, full electronic circuit generator, electrical simulator or natural-language parser.

## 6. Query and result contract

Create immutable, versioned application-level query and result records.

Required query information:

- query ID;
- originating requirement ID;
- board instance ID;
- exact definition ID and digest;
- requested function;
- operating state;
- catalog digest;
- fact-set digest;
- evidence/trust scope.

Each returned terminal candidate must preserve:

- exact `TerminalRef`;
- resolved signal mapping;
- actual verifier findings;
- separate unevaluated coverage;
- evidence claim IDs;
- known limitations;
- qualification state.

Allowed bounded classifications:

- `FUNCTION_CONFIRMED_FOR_STATED_CHECK`
- `KNOWN_UNSUITABLE`
- `UNRESOLVED_EVIDENCE`

A positive GPIO direction result does not establish board availability, electrical compatibility, firmware execution or physical safety.

## 7. Discovery algorithm

1. Validate catalog and fact-set binding.
2. Validate externally supplied expected trust pins.
3. Resolve the requested exact board instance.
4. Enumerate physical terminals from the existing catalog.
5. Identify candidate GPIO contacts using typed mapping data.
6. Preserve unresolved or conflicting mappings.
7. Construct the applicable `GpioRequirement` objects.
8. Invoke `verify_gpio_requirements()`.
9. Classify each physical terminal based on actual scoped results.
10. Return a deterministic, versioned and evidence-linked domain-discovery report.

Do not generate new manufacturer facts.

Do not infer GPIO capability from display labels or sensor names.

5. Frozen validation behavior and errors — Rev 1.1 precedence resolution
Owner decision UX08-T02A-D01: schema validation takes precedence over semantic consistency checks. The Rev 1.0 request to treat a mismatched nested ruleset_version as PROJECTION_INCONSISTENT_NATIVE_RECORD is superseded. In the existing native gpio_verify.py both parent report and nested results have Literal["gpio-capability-v1"]. A different nested ruleset value cannot pass strict Pydantic revalidation. It must return PROJECTION_INVALID_INPUT, not PROJECTION_INCONSISTENT_NATIVE_RECORD. Do not weaken native Pydantic models, bypass type validation, normalize versions, or invent a second accepted ruleset. This change does not add any new error code or API field.

Apply validation in the following fixed order, fail closed, before producing output:
1. Structural/type validity: arguments must be genuine validated instances of exact native TopologyResult, GpioVerificationReport, TerminalRef classes and must pass strict Pydantic revalidation, including nested records. Otherwise PROJECTION_INVALID_INPUT. For any altered model_copy(update=...) object whose value violates a native Literal, digest format, ID constraint, or other schema rule, this error wins over a possible semantic mismatch.
2. Snapshot agreement: topology.snapshot_sha256 != report.snapshot_digest yields PROJECTION_SNAPSHOT_MISMATCH.
3. Selected terminal presence: absent canonical key T:<instance_id>/<terminal_id> in topology.terminal_to_net yields PROJECTION_TERMINAL_NOT_IN_TOPOLOGY.
4. Topology consistency: invalid/missing selected net_id, Net.members, or invalid terminal-to-net membership for records under inspection yields PROJECTION_INCONSISTENT_TOPOLOGY, except a report record’s native affected_net disagreement, which is governed by step 5.
5. Structurally valid but inconsistent native report records: record snapshot_digest, catalog_digest or factset_digest differs from parent report, or affected_net differs from the corresponding native topology net; return PROJECTION_INCONSISTENT_NATIVE_RECORD. A report-record terminal missing from canonical topology is also inconsistent. Parent/nested ruleset_version consistency may be checked defensively but a forged different value necessarily fails step 1 under current native Literals. Do not construct a fake valid ruleset mismatch merely to satisfy the old oracle.
6. Duplicate native record identity: repeated finding_id anywhere across report.findings and report.coverage yields PROJECTION_DUPLICATE_RECORD_ID.
Where multiple conditions are injected simultaneously, the earliest applicable step wins. Acceptance negative tests should ordinarily inject one violation per test. No silently dropped invalid records.

Do not fabricate a generic SOURCE_VERIFIED, CURRENT, STALE, SAFE, 5V_SAFE, global health grade, source URL, citation, voltage judgment or check status. This task does not prove that a passed-in native report is authentic/trusted, nor that its source pins remain current. It only rejects internal inconsistencies detectable from these inputs. topology does not carry a catalog digest, so do not claim to verify the topology's independent catalog trust.

ProjectionInputError.code is the stable machine-readable indicator. No fallback to guessed data, silent enum normalization or correction. The error message may include only non-sensitive identifiers; do not include confidential content or complete source payloads.

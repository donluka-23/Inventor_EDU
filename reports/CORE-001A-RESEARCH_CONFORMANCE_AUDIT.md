## 1. აღმასრულებელი დასკვნა

CORE-001A არის დამტკიცებული კვლევითი კონტრაქტის განხორციელება მნიშვნელოვანი შეზღუდვებით. კოდში პირდაპირ იკითხება Research A-ის გრაფი, `collections.deque`-ზე აგებული BFS, განცალკევებული ფიზიკური კონტაქტები, კანონიკური JSON და SHA-256. AM-01–AM-04-ის ცვლილებები ასახულია ტიპებსა და ტესტებში. ეს კავშირები ქვემოთ მოთხოვნა-მოთხოვნად არის ნაჩვენები.

`SignalMapping`-ის დადასტურებული ხარვეზი ღია რჩება. `J3.9`-ის სამიზნის ტიპის შეცვლამ `soc_gpio`-დან `power_domain`-ზე, იმავე `GPIO18` იდენტიფიკატორითა და ხელახლა დათვლილი კატალოგის ჰეშებით, კვლავ დააბრუნა `verified`. `EvidenceClaim` v1.0-ში სამიზნის ტიპს დამოუკიდებლად ვერ ამოწმებს. შედეგია `SCHEMA_DECISION_REQUIRED`. არსებული 11 ტესტი და დამატებული ორი ტესტი გავიდა. დადებითი GPIO დასკვნისთვის საჭირო მტკიცებულება ჯერ დაუდასტურებელია.

## 7–8. Scientific and provenance checks

Adjacency comes only from the declared undirected conductor pairs and the star-expanded members of an admitted internal tie. A star preserves reachability among the tied group while avoiding a need for all pairwise edges. The visited set means a physical terminal is added to exactly one reachability component. The net hash covers physical membership, not conductor provenance or junction identifiers. The wire-to-net map retains duplicate wire IDs, and the full snapshot digest changes when conductor membership or catalog identity changes. The NetworkX bounded partition oracle, fixed parallel/deletion cases and literal hash vector test different parts of this argument independently.

Nonzero-resistance elements may be described with two contacts. Connectivity never infers an ideal short from component category, logical signal, similar label or geometry. The regulator is excluded from ideal paths by the fixture evidence. No claimed voltage, current, GPIO state, safety case or analytical divider result is emitted. Research C's topology prerequisite for a two-resistor motif is representable, but C still needs a reviewed model of the relationship across individual component terminals.

`_admit_catalog` checks scoped claim IDs and declared status, typed values and documented sources for the relevant operations. Internal ties require exact terminal sets and a compatible declared source class/publisher, and conflicting or incomplete ties are rejected. There is no independent identity/authenticity check on who declared a claim approved. The optional expected catalog digest is effective only if pinned through a separate trusted review. The source-edition probe confirms that claim and source contents are inside the catalog pin and outside the definition pin. Any downstream evidence cache keyed by the definition digest alone can miss a source revision.

## 9–12. Nonconformities, cause, justified deviations and minimum correction

1. **Mapping-kind evidence gap (confirmed).** The mapping model contains `target_kind` but its claim uses a text value for target ID and the condition for the physical contact. Neither the source record nor the approved v1 claim has an independent target-kind datum. The comparison in c168–186 checks target ID, condition, claim kind, document, location, and review/conflicts, plus only that `target_kind` is not `unknown`. The existing fixture only asserts the successful ID resolution, and its tamper case keeps the original digest, so those checks cannot catch a kind-only edit with correct digests. Original Research A required auditable scoped mapping, and the revised contract required compact typed evidence, but they did not specify encoding of independent mapping-kind evidence. R1 now states the full invariant explicitly. Observed causes are under-specified evidence representation and a missing semantic negative test. There is no evidence tying this defect to a missing license gate or an undocumented reasoning history.
2. **Serialization validation boundary (confirmed, separate from the mapping defect).** Calling `serialize_snapshot` on a manually constructed, schema-valid object with nonexistent instances emitted 352 bytes. `restore_snapshot` rejected those bytes with `UNKNOWN_INSTANCE`. `compute_nets` and `resolve_terminal` independently bind before use. Define and test a contract that either restricts serializers to validated outputs or adds explicit semantic binding before publishing untrusted objects. `serialize_topology` also assumes an already-derived result and does not validate graph truth from a raw model. No change requested to those APIs in this correction.
3. **Evidence revision and authentication.** Source-only updates retain the same definition pin and change the catalog pin. This is a documented digest boundary and compatible with the contract when both pins travel together. Without trusted admission, a reseal with self-declared approval can appear internally consistent. Require review and the expected catalog pin for meaningful external evidence trust.
4. **Test gaps.** T07 exact fixture, whole-graph P4 including orphan groups, broad P8 transformations, direct immutability assertion and independent catalog/definition P10 golden vectors are not established as noted in the matrix. The geometry test checks the engineering/view boundary. The lock is specific to Windows x64 CPython 3.12. Other platforms, production-scale performance and physical units were not verified. T18 redistribution lifecycle is outside this runtime.
5. **Justified differences.** Open categories and physical contacts, synthetic fixture labels, no empty electrical net for editing-only groups, no geometry schema, exact unregistered-family rejection and no external EDA engine are authorized or equivalent at the approved boundary. No subsequent GPIO/voltage rule, firmware check, or simulator is an omitted A requirement.

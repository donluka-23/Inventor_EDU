# CORE-001A independent acceptance audit

**Engineering recommendation: ACCEPT_WITH_RESTRICTIONS.** The core is suitable for deterministic connectivity over reviewed, pinned catalogs and validated snapshots. Verified mapping metadata needs an additional evidence check before it can support a positive GPIO finding. This is an audit recommendation for architecture-owner review.

### Generalization

`DeviceDefinition.device_class` and `TerminalDefinition.contact_type` use open validated identifiers. Connector fields and signal mappings are optional. Definitions can omit ties. The four existing fixture categories cover development board header contacts, sensor contacts, a two-lead passive, and a multi-pad opaque device (`tests/core001a_fixtures.py:70–138`). Tests show the passive leads and opaque device pads become separate singleton nets until explicitly wired. Both synthetic profiles establish representation without GPIO or a behavioral model. The production graph only uses terminal keys, conductors, junctions and admitted tie membership.

### Public API inventory

`inventor_edu/__init__.py:3–22` exports seven functions. In `inventor_edu/core.py` they are:

- `load_catalog` (208) validates the supplied catalog and optional expected digest.
- `create_snapshot` (284) and `restore_snapshot` (325) validate and normalize circuit state.
- `resolve_terminal` (296) returns the physical reference, definition ID, terminal record and claim IDs.
- `compute_nets` (331) returns the snapshot digest, nets, mappings, isolated terminals and editing diagnostics.
- `serialize_snapshot` (315) and `serialize_topology` (394) emit deterministic UTF-8 for admitted workflow objects.

Exported records are `CatalogSnapshot`, `CircuitSnapshot`, `ComponentInstance`, `Conductor`, `DeviceDefinition`, `DeviceIdentity`, `EvidenceClaim`, `InternalIdealTie`, `Junction`, `JunctionRef`, `ResolvedTerminal`, `SignalMapping`, `SourceDocument`, `TerminalDefinition`, `TerminalRef`, `TopologyResult` and `EngineeringModelError`. Nets and diagnostic items are available through the topology result. Python mappings in the result are immutable key/value tuples. JSON represents them as objects. No public catalog authoring or topology restoration API is exported.
